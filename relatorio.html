QUESTÕES Conceitos aplicados

1Qual é a função do comando docker build?

Ele lê o Dockerfile e o contexto de build (a pasta indicada no fim do comando, aqui o ponto) e executa as instruções na ordem em que aparecem, gerando uma camada a cada uma delas. O produto final é uma imagem pronta, armazenada localmente. A opção -t dá o nome pelo qual essa imagem passa a ser chamada — foi assim que java-produtos e java-cti-insights surgiram.

2Qual é a diferença entre uma imagem Docker e um container Docker?

A imagem é o pacote pronto e imutável — um sistema de arquivos em camadas com o JDK 21 e os .class já compilados, mais a instrução de inicialização. Ela não executa nada sozinha; fica guardada, como um molde.

O container é uma instância em execução dessa imagem: o Docker acrescenta uma camada de escrita por cima e roda o processo isolado do restante do sistema. Uma mesma imagem pode originar vários containers simultâneos e independentes e, ao encerrar o container (com --rm, que o apaga), a imagem permanece intacta para o próximo docker run.

3Para que serve a instrução FROM dentro do Dockerfile?

Define a imagem base sobre a qual todas as demais camadas são empilhadas e, por isso, é a primeira instrução do arquivo. Nestas atividades, FROM eclipse-temurin:21-jdk entrega um Linux que já vem com o JDK 21 instalado — é o que permite chamar javac e java nas instruções seguintes sem instalar nada manualmente.

4Qual é a função do comando COPY no Dockerfile?

Copia arquivos e pastas do contexto de build, na máquina host, para dentro do sistema de arquivos da imagem. Sem ele o código-fonte simplesmente não existiria lá dentro: COPY *.java ./ leva os sete arquivos da CTI Insights para o /app definido no WORKDIR, onde o javac vai encontrá-los.

5Qual é a vantagem de executar um programa Java dentro de um container em vez de depender do Java instalado no computador?

Porque a versão do Java deixa de ser uma característica da máquina e passa a fazer parte da própria aplicação:

  • Reprodutibilidade — a imagem carrega o JDK 21 exato, então o programa roda igual no notebook do aluno, no computador do professor e no servidor, eliminando o clássico "na minha máquina funciona".
  • Sem conflito de versões — não importa se o host tem Java 8, Java 17 ou nenhum Java, nem como o JAVA_HOME está configurado.
  • Isolamento — o processo roda em ambiente separado, sem interferir em outras aplicações da máquina nem sofrer interferência delas.
  • Portabilidade — a mesma imagem pode ser enviada a um registry e executada em qualquer host com Docker, o que é justamente a base para publicá-la em nuvem.
  • Descarte fácil — encerrado o container, a máquina fica exatamente como estava antes.
